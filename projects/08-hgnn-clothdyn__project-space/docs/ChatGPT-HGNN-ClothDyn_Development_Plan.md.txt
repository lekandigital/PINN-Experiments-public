## Step 2: Mesh to Graph Conversion (Geodesic Adjacency & Graph Pyramid)

In this step, we convert a cloth mesh (from Blender/Houdini or an OBJ file) into a graph data structure and build a multi-resolution graph pyramid for hierarchical GNN processing. The graph’s nodes represent cloth vertices, and edges represent geodesic neighbor connections along the cloth surface (typically the mesh’s original edges). We then construct coarse graphs by clustering the fine mesh vertices, creating a hierarchy of graphs (levels) that the hierarchical GNN will utilize.

```python
import numpy as np
import torch
from torch_geometric.data import Data
from torch_geometric.nn.pool import graclus, max_pool

# Sample input: vertices (V x 3 array) and faces (F x 3 array) from a mesh.
vertices = np.array([...])  # e.g., loaded from a .obj file using a library or custom parser
faces = np.array([...])     # each row has 3 vertex indices defining a triangle

# 1. Build geodesic adjacency (edge index) from faces.
# We treat each mesh edge as an undirected graph edge.
edges = set()
for tri in faces:
    i, j, k = int(tri[0]), int(tri[1]), int(tri[2])
    # add all three edges of the triangle (undirected)
    edges.add((i, j)); edges.add((j, i))
    edges.add((i, k)); edges.add((k, i))
    edges.add((j, k)); edges.add((k, j))
# Convert edge set to tensor of shape [2, E]
edge_index = torch.tensor([[u, v] for (u, v) in edges], dtype=torch.long).t().contiguous()

# 2. Create initial graph Data for PyTorch Geometric.
pos = torch.tensor(vertices, dtype=torch.float)        # node positions
data_lv0 = Data(x=pos, pos=pos, edge_index=edge_index)  # use pos as initial features (x)

# 3. Compute a coarser graph level (level 1) using clustering (Graclus).
cluster = graclus(data_lv0.edge_index, num_nodes=data_lv0.num_nodes)  # cluster assignment for each node
data_lv1 = max_pool(cluster, data_lv0)  # pools node features and edges to coarse graph
# data_lv1.x now contains averaged features per cluster, and data_lv1.edge_index is the coarse graph connectivity.

# Optionally, create an even coarser level (level 2) by clustering level 1:
cluster1 = graclus(data_lv1.edge_index, num_nodes=data_lv1.num_nodes)
data_lv2 = max_pool(cluster1, data_lv1)

# Now we have a graph pyramid: level 0 (original), level 1 (coarser), level 2 (coarsest).
print(f"Level0: {data_lv0.num_nodes} nodes, {data_lv0.num_edges} edges")
print(f"Level1: {data_lv1.num_nodes} nodes, {data_lv1.num_edges} edges")
print(f"Level2: {data_lv2.num_nodes} nodes, {data_lv2.num_edges} edges")
```

**Explanation:** First, we parse the mesh’s vertices and faces to get adjacency: each triangle’s edges form connections between vertex indices. We build a PyTorch Geometric `Data` object with node features `x` (here initialized as the 3D coordinates, which can serve as input features) and `edge_index` defining connections. Using `graclus` clustering, we group nodes into clusters (roughly by geodesic proximity on the mesh) and then use `max_pool` to collapse each cluster into a single node in a coarse graph. This produces a **graph pyramid** (`data_lv0`, `data_lv1`, `data_lv2`), where level 0 is the full detail cloth, and higher levels have fewer nodes. Each coarse node represents a region of cloth, enabling the model to reason at multiple spatial scales. The code prints out the number of nodes/edges at each level for verification.

*Detailed comments:* We use **geodesic adjacency** meaning connectivity along the surface: here it’s equivalent to the mesh’s intrinsic adjacency (we don't connect distant vertices that aren’t directly connected by the cloth). The clustering algorithm (Graclus) greedily merges vertices to form coarse nodes, preserving graph structure for multi-resolution processing. This hierarchical representation will allow our HGNN to perform **message passing at multiple scales** (e.g., coarse level for global movements, fine for local details). The conversion script is kept framework-agnostic (just using PyTorch Geometric utilities), and can be adapted – e.g., for a structured cloth (grid mesh), one could cluster by quads or subsampling. By adjusting clustering granularity, this approach supports different GPU memory settings: e.g., on a 24 GB GPU you might use more hierarchy levels or larger graphs, whereas on lower VRAM you can cluster more aggressively to reduce graph size.

## Step 3: Hierarchical GNN Model Implementation (PyTorch Geometric)

In this step, we implement the HGNN-ClothDyn model using PyTorch Geometric. The model performs hierarchical message passing across the graph pyramid levels, incorporates learned edge stiffness (to model spring-like cloth behavior), and uses node features encoding velocities and other attributes (like collisions) to predict cloth dynamics. The architecture is modular and designed to run on both high-end (24 GB GPU) and lower-memory setups by adjusting layer widths or hierarchy depth.

Below is the code for the hierarchical GNN model. We define custom message-passing to include edge stiffness, and we utilize a coarse-to-fine mechanism: messages propagate on the fine graph, then global context is gathered via the coarse graph, and finally refined back at the fine level. Comments explain each part:

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch_geometric.nn import MessagePassing
from torch_geometric.utils import scatter

class EdgeForceConv(MessagePassing):
    """Custom message passing that computes spring-like forces on edges."""
    def __init__(self, in_channels):
        super().__init__(aggr='add')  # aggregate messages by summation
        # MLP to compute edge stiffness factor from features (like rest length)
        self.edge_mlp = nn.Sequential(
            nn.Linear(1, in_channels), nn.ReLU(), 
            nn.Linear(in_channels, 1)
        )
    def forward(self, x, edge_index, rest_len):
        # x: node feature matrix [N, F], rest_len: edge attribute [E, 1] (rest lengths)
        return self.propagate(edge_index, x=x, rest_len=rest_len)
    def message(self, x_i, x_j, rest_len):
        # x_i, x_j: features of source & target nodes for each edge
        # Compute current edge vector and length
        vec_ij = x_j[:, :3] - x_i[:, :3]   # using first 3 dims of x as positions
        curr_len = torch.norm(vec_ij, p=2, dim=1, keepdim=True)
        strain = (curr_len - rest_len) / (rest_len + 1e-8)  # relative deformation
        # Compute stiffness factor via MLP (learned spring response)
        stiffness = self.edge_mlp(strain)  # outputs a scalar per edge
        force = stiffness * vec_ij  # directional force proportional to displacement
        return force
    def update(self, aggr_out):
        # The aggregated result is the sum of forces from neighbors; use as acceleration
        return aggr_out

class HGNNClothDyn(nn.Module):
    def __init__(self, node_feat_dim=6, hidden_dim=128):
        """
        Hierarchical GNN for cloth dynamics.
        node_feat_dim: e.g., 6 (3 position + 3 velocity as input features per node).
        hidden_dim: size of hidden features (adjust for VRAM: lower if memory is limited).
        """
        super().__init__()
        self.hidden_dim = hidden_dim
        # Encoder layers for fine level
        self.input_mlp = nn.Linear(node_feat_dim, hidden_dim)
        # Message passing conv on fine level
        self.fine_conv1 = EdgeForceConv(hidden_dim)
        # Message passing conv on coarse level (global interactions)
        self.coarse_conv = EdgeForceConv(hidden_dim)
        # Decoder conv on fine level after merging coarse info
        self.fine_conv2 = EdgeForceConv(hidden_dim)
        # Output layer: predict velocity update (delta v) and collision impulse
        self.out_mlp = nn.Linear(hidden_dim, 3)  # output 3D vector per node (could represent acceleration or pos delta)
        # (We can output 3 channels: here treating it as position/velocity change. Collision impulses will be learned as part of this output if applicable.)
    
    def forward(self, data_lv0, data_lv1, assign_idx):
        """
        Forward pass of HGNN-ClothDyn.
        data_lv0: Data for fine graph (level 0).
        data_lv1: Data for coarse graph (level 1).
        assign_idx: Tensor of shape [N_lv0] giving the cluster assignment of each fine-level node to a coarse-level node.
                    (This comes from the clustering step in Step 2.)
        """
        # 1. Fine-level initial encoding
        x0 = F.relu(self.input_mlp(data_lv0.x))          # shape [N0, hidden_dim]
        # 2. Fine-level local message passing (capture local cloth interactions)
        # Compute rest lengths for fine edges (could be precomputed and stored in data)
        if 'rest_len' in data_lv0:
            rest_len0 = data_lv0.rest_len
        else:
            # If not provided, calculate rest lengths from initial positions (assuming data_lv0.pos has rest pose coords)
            edge_src, edge_dst = data_lv0.edge_index
            vec = data_lv0.pos[edge_dst] - data_lv0.pos[edge_src]
            rest_len0 = torch.norm(vec, p=2, dim=1, keepdim=True)
        x0_updated = self.fine_conv1(x=x0, edge_index=data_lv0.edge_index, rest_len=rest_len0)
        x0 = x0 + F.relu(x0_updated)  # update fine features (residual connection)
        
        # 3. Pool to coarse level: aggregate fine features to coarse nodes
        # We average features of fine nodes belonging to the same coarse cluster
        N1 = data_lv1.num_nodes
        assign_idx = assign_idx.to(x0.device)  # ensure it's on correct device
        x1 = scatter(x0, assign_idx, dim=0, dim_size=N1, reduce='mean')  # [N1, hidden_dim]
        data_lv1.x = x1  # set coarse node features
        
        # 4. Coarse-level global message passing (capture global cloth dynamics)
        # (Compute or use stored coarse rest lengths similarly)
        if 'rest_len' in data_lv1:
            rest_len1 = data_lv1.rest_len
        else:
            edge_src, edge_dst = data_lv1.edge_index
            vec = data_lv1.pos[edge_dst] - data_lv1.pos[edge_src]
            rest_len1 = torch.norm(vec, p=2, dim=1, keepdim=True)
        x1_updated = self.coarse_conv(x=x1, edge_index=data_lv1.edge_index, rest_len=rest_len1)
        x1 = x1 + F.relu(x1_updated)
        
        # 5. Upsample coarse info back to fine: 
        # Assign each fine node the updated coarse feature of its cluster
        coarse_feat_expanded = x1[assign_idx]  # [N0, hidden_dim], each fine node gets its coarse cluster's feature
        # Combine coarse and fine features (e.g., concatenate or add)
        x0_combined = x0 + coarse_feat_expanded  # here we add, could also cat and use another linear layer
        
        # 6. Fine-level second pass message passing (refine with global context)
        x0_refined = self.fine_conv2(x=x0_combined, edge_index=data_lv0.edge_index, rest_len=rest_len0)
        x0_final = x0_combined + F.relu(x0_refined)
        
        # 7. Output prediction per node (e.g., velocity delta including collision impulse effects)
        output = self.out_mlp(x0_final)  # [N0, 3]
        return output
```

**Model explanation:** The `HGNNClothDyn` class is our hierarchical GNN. It expects a fine graph (`data_lv0`) and a coarse graph (`data_lv1`), along with an `assign_idx` mapping fine nodes to coarse nodes (obtained from clustering in Step 2).

- **Node features:** We assume each node’s input feature vector includes its position and velocity (3 + 3 = 6 dimensions) and possibly other info (like a collision flag or external force). This dimension is `node_feat_dim`. The model linearly encodes these features to `hidden_dim`. (One can adjust `hidden_dim` based on memory: e.g., use 64 for low VRAM, 128 or 256 for high VRAM to capture more detail.)

- **EdgeForceConv:** This is a custom GNN message-passing layer modeling spring forces. It calculates the vector between neighbor nodes (`vec_ij`) and compares current length to rest length to compute a strain. A small MLP (`edge_mlp`) then produces a learned stiffness factor, essentially allowing the network to scale the force based on edge strain in a nonlinear way (this mimics cloth stiffness: edges that are too stretched or slack can generate restoring forces). The message returned is `force = stiffness * vec_ij`, which is added to the target node as an aggregated message (representing force/acceleration contribution from that neighbor). This mechanism lets the model learn how cloth tension translates to node motion, instead of using a fixed physical spring constant.

- **Hierarchical message passing:** We perform **two passes on the fine graph** (before and after a coarse pass):
  1. **Fine pass 1:** `fine_conv1` sends messages on the level-0 graph, capturing **local interactions** (adjacent vertices exchange forces, e.g., stretch/bend forces along cloth). We use a residual update (`x0 = x0 + ...`) to stabilize training (like adding the computed acceleration to the current state).
  2. **Pooling to coarse:** We use the `assign_idx` to **aggregate fine node features into coarse node features**, here by taking the mean of all fine features in a cluster. This gives `x1`, representing a coarse-level state (like a summary of an entire patch of cloth).
  3. **Coarse pass:** `coarse_conv` operates on the coarse graph (`level 1`), which has far fewer nodes. This captures **global interactions** efficiently. For instance, it can propagate information across the cloth with fewer message-passing hops. (E.g., if the cloth has separate regions or long-distance correlations – the coarse graph will connect them with short paths.) We again do a residual update on `x1`.
  4. **Upsample to fine:** Each fine node takes on its coarse cluster’s updated feature (`coarse_feat_expanded`). We combine this with the fine-level features (here we simply add them, treating the coarse feature as a global context adjustment for the fine node’s state).
  5. **Fine pass 2:** `fine_conv2` then does another round of message passing on the fine graph, now with nodes aware of global context. This refines the local predictions, possibly adjusting for global cloth motions (e.g., if a global movement caused tension changes, now local edges respond accordingly).

- **Output:** Finally, an output MLP produces a 3D vector per node. This could be interpreted as the predicted change in velocity (or position) for the next time step. In our design, this output inherently includes any **collision impulses** or external force effects, because those must be reflected in how the network updates velocities. For example, if a node is colliding, the training data will have a sudden velocity change; the network will learn to output an appropriate impulse (change in velocity) when it detects a collision scenario in the features. We could optionally split the output into, say, predicted acceleration and a separate binary collision impulse indicator, but here we keep it unified for simplicity – the model will learn to spike the output vector when a collision is needed.

The model is kept **modular**: `EdgeForceConv` encapsulates the message computation (and could be replaced with a standard GCN or GraphConv if one wanted a simpler interaction). We use simple residual connections and MLPs; one could extend this with more layers (e.g., stacking multiple `EdgeForceConv` per level) for a deeper model if the GPU allows. We also designed it such that it does not explicitly store large intermediate tensors (besides what PyG needs), and one can reduce `hidden_dim` or remove one hierarchical level if memory is a concern.

This implementation assumes that `data_lv0.pos` and `data_lv1.pos` contain the rest (initial) positions to compute `rest_len`. In practice, we would compute and store `rest_len` once (e.g., as `data_lv0.rest_len`) to avoid recalculating each forward pass. Also, for **collision handling**, one may include additional node features: e.g., a boolean flag if a node is in contact with an object, or the collision normal and penetration depth. Such features can be appended to `node_feat_dim` and the network will learn to incorporate them (for instance, to output an opposing impulse). The hierarchical approach and learned stiffness allow the network to handle collisions and deformation in a unified way: e.g., a collision essentially is a constraint that the network can learn to mimic by outputting a velocity change (impulse) that prevents interpenetration.

*Compatibility:* On a 24 GB GPU, one can use `hidden_dim=128` or higher and perhaps additional GNN layers for finer modeling. On a lower-memory GPU, reducing `hidden_dim` or bypassing the second fine pass (for a simpler one-level GNN) would lighten memory usage. The code structure makes it easy to adjust these: for example, replacing the custom conv with simpler ones or removing the coarse level (set `assign_idx` to identity and skip pooling) would degrade performance but help in very constrained environments. Overall, the model is designed to be **scalable** – by changing the cluster granularity and feature widths, the same code can run across hardware with different capabilities.

## Step 4: Training Script with Teacher Forcing and Scheduled Sampling

Training HGNN-ClothDyn involves predicting cloth node states over time. We use a temporal rollout approach: given a sequence of ground-truth states (from a simulator dataset), the model is rolled out to predict the next states. **Teacher forcing** means that during training we feed the model the actual ground-truth state from the previous time-step (rather than its own prediction) to predict the next state. This stabilizes training early on. **Scheduled sampling** gradually introduces the model’s own predictions into its inputs during training, to teach it to handle compounding errors during long rollouts (improving stability at inference time). We provide toggles to switch between pure teacher forcing and scheduled sampling modes.

Below is a training loop pseudocode with commentary on how teacher forcing and scheduled sampling are implemented:

```python
import torch
import torch.optim as optim

# Assume we have a dataset of sequences of cloth states (pos & vel per frame)
# Each sequence is a tensor of shape [T, N, feature_dim] (feature_dim = 6 for pos+vel).
# We also assume we have precomputed graph structures (data_lv0, data_lv1, assign_idx as in Steps 2-3).
# For simplicity, let's call our model 'model' (an instance of HGNNClothDyn).

# Hyperparameters
epochs = 50
lr = 1e-3
use_scheduled_sampling = True

optimizer = optim.Adam(model.parameters(), lr=lr)

# Function to get model input from a state (pos, vel)
def state_to_data(state):
    # state: [N, 6] tensor of pos(3) and vel(3)
    data_lv0 = Data(x=state, pos=state[:, :3], edge_index=edge_index_lv0, rest_len=rest_len_lv0)
    # Note: We reuse the same rest_len and edge_index each time (cloth topology is constant).
    return data_lv0

for epoch in range(epochs):
    model.train()
    epoch_loss = 0.0
    # Loop over training sequences
    for seq in train_dataset: 
        # seq shape: [T, N, 6]
        T = seq.shape[0]
        # Initialize: start from the first frame's state
        prev_state = seq[0]  # [N,6] (initial positions and velocities)
        # Optionally, we could initialize model hidden states here if it had an RNN (not needed in our feedforward design).
        for t in range(1, T):
            # Prepare input for time t prediction
            if use_scheduled_sampling and epoch > 5:  # start scheduled sampling after a few epochs
                # Linearly increase the chance of using model's own prediction as input as training progresses
                sampling_prob = min(1.0, 0.1 + 0.05 * epoch)  # e.g., start at 10%, increase 5% per epoch
                use_model_prev = (torch.rand(1).item() < sampling_prob)
            else:
                use_model_prev = False  # pure teacher forcing in early epochs or if scheduling off
            
            # Determine the state input for this step
            if use_model_prev:
                # Use model's previous prediction as input (simulate rollout)
                curr_input_state = prev_state_pred.detach()  # detach from graph to avoid backprop through this usage
            else:
                # Use ground-truth previous state
                curr_input_state = prev_state
            
            # Convert current input state to graph Data
            data_lv0 = state_to_data(curr_input_state)
            data_lv1 = data_lv1_template.clone()  # coarse graph structure (pos may be updated if needed)
            # Run model forward to predict state change (delta)
            delta = model(data_lv0, data_lv1, assign_idx)
            # Predicted next state = current state + delta (assuming delta represents velocity*dt or position change)
            prev_state_pred = curr_input_state.clone()
            prev_state_pred[:, :3] += delta  # update positions (simple Euler integration: pos_next = pos + delta_pos)
            # If the model outputs velocity delta instead, we would update velocity and then integrate positions accordingly.
            
            # Compute loss between prediction and ground truth at time t
            gt_state = seq[t]  # ground truth state at time t
            pos_loss = torch.nn.functional.mse_loss(prev_state_pred[:, :3], gt_state[:, :3])
            # Optionally include velocity loss if we predict velocities
            # vel_loss = mse(prev_state_pred[:,3:], gt_state[:,3:])
            loss = pos_loss  # (add other terms as needed)
            # Backpropagate and optimize
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            
            epoch_loss += loss.item()
            # Update prev_state for next step in teacher-forcing mode
            prev_state = gt_state  # use actual ground truth for next step unless scheduled sampling overrides
    print(f"Epoch {epoch}: avg loss = {epoch_loss/len(train_dataset):.6f}")
```

**Training loop explanation:** We iterate through each epoch and each training sequence of cloth simulation frames. For each sequence:

- We take the first frame as the initial state (`prev_state`). Then for each subsequent time step `t`, we decide what to feed the model as the previous state:
  - If `use_scheduled_sampling` is false (or if we are in initial epochs), we always use the *ground truth* previous state (`prev_state = seq[t-1]`). This is standard **teacher forcing** – the model sees correct history.
  - If scheduled sampling is enabled and we are sufficiently into training, we draw a random coin flip (`use_model_prev`) with probability `sampling_prob` (which increases over epochs). If this is true, we use the model’s **own last predicted state** (`prev_state_pred`) as the input for the next prediction; if false, we fall back to ground truth. Over training, `sampling_prob` might anneal from 0 up to 1 (or some maximum), meaning we progressively trust the model’s outputs more often.
- We then construct the graph input for the model from `curr_input_state`. The helper `state_to_data` creates a PyG `Data` object for level 0 using the current positions/velocities. We also prepare `data_lv1` (the coarse level graph). Here, `data_lv1_template` is presumably a precomputed Data with correct topology; we might update its node positions if needed (though in this simple approach, we might keep using rest positions for coarse since dynamic positions aren’t as crucial for force calculation at coarse scale).
- The model outputs a `delta` (interpreted as change in position for this timestep). We then form `prev_state_pred` by adding this delta to the current state’s positions. (In a more physically grounded setup, `delta` could be velocity \* dt, or we might integrate velocity and position separately. Here for simplicity, we treat the network output as the positional offset per frame.)
- We compute a loss between the predicted state and the ground-truth state at time `t`. We use Mean Squared Error (MSE) on positions; optionally, one could include velocity loss or strain energy loss, etc., to encourage physical realism. If collisions are involved, the model must predict the correct post-collision position – the loss naturally guides it to output appropriate impulses.
- We backpropagate this loss and update the model parameters. We then continue to the next time step. Note that even if we used the model’s prediction as input (scheduled sampling), we *still* compare the prediction to the true `gt_state` for loss – the difference is only in what the model sees as input.

The loop uses teacher forcing by default (especially in early epochs, `use_model_prev` will be false). As training progresses, scheduled sampling kicks in (the probability of feeding back the model’s own prediction increases). This helps the model handle compounding errors: early on, it learns the one-step prediction well (with teacher forcing); later, it practices recovering from slight off-track inputs (since it might get its own somewhat imperfect prediction as input).

We print the average loss per epoch to monitor training. Over time, we expect the loss to decrease and the model to produce stable rollouts.

**Toggles and modes:** The variable `use_scheduled_sampling` can turn the whole mechanism on or off. If off, the code always uses ground truth (pure teacher forcing). One could also introduce a curriculum schedule manually – e.g., only start scheduled sampling after a certain epoch (as we did with `if epoch > 5`), or adjust `sampling_prob` schedule (linear, exponential decay of teacher forcing, etc.). The straightforward linear increase shown (`0.1 + 0.05*epoch`) is just an example; in practice one might cap it below 1.0 or use a more sophisticated schedule (as per Bengio et al.’s scheduled sampling technique).

During **evaluation (testing)**, we of course do not have ground truth for future frames, so we always use the model’s own predictions – essentially the trained model should by then handle this scenario, thanks to the scheduled sampling training. The training script above focuses on one-step loss; one could accumulate multi-step rollout loss as well (comparing prediction 5 steps out to ground truth, for instance) to further improve long-horizon accuracy.

## Step 5: Dataset Export Script (Blender/Houdini to HDF5/CSV)

To train and evaluate HGNN-ClothDyn, we need cloth simulation data. Here, we outline a script to run a cloth simulation in Blender (which has a built-in physics engine for cloth) and export the results (per-frame node positions, connectivity, and collision info) in a structured format (like HDF5 or CSV). This script can be adapted to Houdini (using Hou’s Python API similarly). We will illustrate with Blender’s `bpy` API.

**Use case:** Suppose we have a cloth object in Blender named `"Cloth"` with a cloth physics modifier, and perhaps a static collision object (like a ground plane named `"Collider"`). We want to simulate a number of frames and record the cloth’s vertices positions each frame, the mesh’s edge list, and any collisions.

Below is a Blender Python script (to be run in Blender’s scripting environment) with detailed comments:

```python
import bpy
import bmesh
import numpy as np
import h5py

# User settings:
cloth_obj_name = "Cloth"     # Name of the cloth object in Blender
collider_obj_name = "Collider"  # Name of a collision object (optional)
start_frame = 1
end_frame = 250
output_path = "/tmp/cloth_simulation.h5"  # output file path (HDF5 format)

# Ensure the scene is set up
scene = bpy.context.scene
scene.frame_start = start_frame
scene.frame_end = end_frame

cloth_obj = bpy.data.objects[cloth_obj_name]
collider_obj = bpy.data.objects.get(collider_obj_name, None)

# (Optional) If cloth simulation not baked, we can loop through frames to ensure simulation runs
for frame in range(start_frame, end_frame + 1):
    scene.frame_set(frame)
    bpy.context.view_layer.update()  # update physics simulation to this frame

# After running simulation, collect data
vertices_seq = []  # will store array of shape (frames, num_vertices, 3)
collision_seq = [] # will store collision data per frame (e.g., list of collided vertex indices)
edges = None

# Get static edge topology from cloth mesh
mesh = cloth_obj.data
# Edges can be extracted from mesh edges or from polygon loops
edges = [(edge.vertices[0], edge.vertices[1]) for edge in mesh.edges]
edges = np.array(edges, dtype=np.int32)

for frame in range(start_frame, end_frame + 1):
    scene.frame_set(frame)
    bpy.context.view_layer.update()
    # Access cloth mesh eval (deformed by physics at this frame)
    cloth_eval = cloth_obj.evaluated_get(bpy.context.view_layer)
    mesh_eval = cloth_eval.to_mesh()  # get mesh data at current frame
    
    # Get vertex positions
    verts = np.array([v.co[:] for v in mesh_eval.vertices], dtype=np.float32)
    vertices_seq.append(verts)
    
    # Determine collisions for this frame:
    collided_verts = []
    if collider_obj:
        # Simple collision check: if cloth vertex is below ground (z < 0) or inside collider bounds
        # (For robust check, one might use distance from collider or bounding box overlap)
        for i, v in enumerate(verts):
            if v[2] < 0:  # assuming ground plane at z=0
                collided_verts.append(i)
    # For self-collision, one would need a more complex check (not done here).
    collision_seq.append(np.array(collided_verts, dtype=np.int32))
    
    # Free the evaluated mesh to avoid memory leak
    cloth_eval.to_mesh_clear()

# Convert to numpy arrays
vertices_seq = np.stack(vertices_seq, axis=0)  # shape: [num_frames, num_verts, 3]

# Save data to HDF5
with h5py.File(output_path, "w") as h5f:
    h5f.create_dataset("vertices", data=vertices_seq)  # positions of vertices over time
    h5f.create_dataset("edges", data=edges)            # edge list (constant for all frames)
    # Store collisions in a group per frame (variable length per frame)
    coll_grp = h5f.create_group("collisions")
    for f, coll in enumerate(collision_seq, start=start_frame):
        coll_grp.create_dataset(str(f), data=coll)
print(f"Exported cloth simulation to {output_path}")
```

**Script explanation:** This script uses Blender’s `bpy` module. Key steps:

- We identify the cloth object and (optionally) a collider object by name.
- We set the frame range for simulation. If the simulation is not baked (i.e., Blender hasn’t precomputed it), we manually advance through each frame (`scene.frame_set(frame)`) and call `update()` to ensure the physics sim runs. This effectively “bakes” on the fly.
- We retrieve the mesh’s edge connectivity from the cloth object’s mesh data (since topology doesn’t change, we do this once outside the frame loop). The edge list is stored as pairs of vertex indices.
- For each frame, we set the scene to that frame, get the evaluated mesh (`obj.evaluated_get` gives the mesh with modifiers applied at that frame, including cloth deformation). We copy the vertex coordinates into a NumPy array.
- Collision detection: As a simple example, we check if any vertex’s z-coordinate is below 0 (assuming a ground plane at z=0). Those vertex indices are marked as collided. If there’s a complex collider (like a sphere), one could check distance from the sphere’s center or use Blender’s physics collision data if accessible. (Blender doesn’t directly expose collision impulses per vertex in Python, so a heuristic or custom detection is used.)
- We collect the vertices and collisions for each frame. `vertices_seq` becomes an array of shape `[frames, verts, 3]`.
- We then write to an HDF5 file: the vertices dataset, the static edge list, and a group of collisions where each frame’s collisions are stored in a separate dataset (named by frame number). If CSV is preferred, one could output `vertices_seq[frame]` to a CSV per frame or a single CSV with frame index, but HDF5 is more structured (and efficient for large data).

The output file (cloth\_simulation.h5) will contain all necessary data for training:

- `vertices` dataset: coordinates of each vertex at each frame.
- `edges` dataset: the cloth mesh connectivity (used to build the graph).
- `collisions` group: for each frame, indices of vertices in collision (with ground or other objects). This can be used to create a collision feature for the model (e.g., set a flag on those vertices or apply an impulse loss).

**Reuse and adaptation:** The script is heavily commented to facilitate modifications. For example, in Houdini, one would use the Hou API to get geometry at each frame similarly. If the cloth simulation is already done in another program, one could skip the physics part and just read the geometry data. The collision detection part may need tailoring to the specific scenario (different collider shapes or self-collision logging). The key is that we export in a **consistent format**. Our training script in Step 4 assumes sequences of positions (and possibly we can derive velocities by finite differences between frames). With this data file, we can load it in Python (using `h5py` or pandas for CSV) to feed the training process.

## Step 6: Benchmarking Tool (Roll-out Stability, FPS, Edge-Length Error)

After training the HGNN-ClothDyn model, we need to evaluate its performance. This includes:

- **Roll-out stability:** how well the model can simulate many time steps without deviating from the ground truth (or without blowing up physically). We quantify this by measuring the divergence of the predicted cloth state from the ground-truth simulation over time.
- **Speed (FPS):** how many simulation frames per second the model can generate, to assess real-time capability.
- **Edge-length error:** how well the model preserves cloth constraints, e.g., difference in edge lengths between the predicted cloth and ground truth (or rest length).

We develop a benchmarking script that computes these metrics and generates plots for visualization.

```python
import numpy as np
import time
import matplotlib.pyplot as plt

# Assume we have loaded a trained model and a test sequence of ground truth states 'gt_seq'
# gt_seq: numpy array of shape [T, N, 3] for positions (for simplicity focusing on positions).
# Also assume we have the graph data structures from earlier (data_lv0, data_lv1, assign_idx, rest_len).

# 1. Roll-out the model on the test sequence:
init_state = gt_seq[0]  # starting positions
pred_positions = [init_state]
state = init_state.copy()
model.eval()
with torch.no_grad():
    start_time = time.time()
    for t in range(1, len(gt_seq)):
        # Prepare graph input from current state
        data_lv0 = Data(x=torch.tensor(np.hstack([state, np.zeros_like(state)]), dtype=torch.float), 
                        pos=torch.tensor(state, dtype=torch.float), 
                        edge_index=edge_index_lv0, rest_len=rest_len_lv0)
        data_lv1 = data_lv1_template.clone()
        # Model predicts delta
        delta = model(data_lv0, data_lv1, assign_idx).cpu().numpy()
        # Update state (positions); here delta is pos change
        state = state + delta
        pred_positions.append(state)
    end_time = time.time()

pred_positions = np.array(pred_positions)  # shape [T, N, 3]
# Ground truth positions for comparison:
gt_positions = gt_seq  # (assuming gt_seq already just positions)

# 2. Compute metrics:
T = pred_positions.shape[0]
# Compute per-frame position error (RMSE)
pos_error = np.zeros(T)
for t in range(T):
    diff = pred_positions[t] - gt_positions[t]
    pos_error[t] = np.sqrt(np.mean(np.sum(diff**2, axis=1)))  # root mean square error per vertex

# Compute edge length error (per frame)
# First get rest lengths (or initial lengths) and edge list
edge_array = edges  # from dataset (shape [E,2])
rest_lengths = np.linalg.norm(gt_positions[0][edge_array[:,0]] - gt_positions[0][edge_array[:,1]], axis=1)
edge_error = np.zeros(T)
for t in range(T):
    pred_lengths = np.linalg.norm(pred_positions[t][edge_array[:,0]] - pred_positions[t][edge_array[:,1]], axis=1)
    gt_lengths = np.linalg.norm(gt_positions[t][edge_array[:,0]] - gt_positions[t][edge_array[:,1]], axis=1)
    # e.g., mean absolute difference between pred and gt edge lengths
    edge_error[t] = np.mean(np.abs(pred_lengths - gt_lengths))

# Compute FPS:
total_time = end_time - start_time
fps = (T-1) / total_time
print(f"Simulation FPS (model rollout): {fps:.2f} frames/sec over {T} frames")

# 3. Plot the error metrics:
plt.figure(figsize=(6,4))
plt.plot(range(T), pos_error, label='Position RMSE')
plt.plot(range(T), edge_error, label='Edge Length Error')
plt.xlabel('Frame')
plt.ylabel('Error')
plt.title('Rollout Error vs Frame')
plt.legend()
plt.tight_layout()
plt.savefig("rollout_error_plot.png")
```

In this script:

- We take an initial ground truth state and roll out the model for `T-1` steps. We measure time to compute FPS. (Ensure that this timing excludes data loading overhead and focuses on model inference.)
- We calculate **position error** per frame: here we use Root Mean Square Error (RMSE) of all vertex positions compared to ground truth. This indicates divergence: ideally it stays low; if it grows over frames, the model is drifting from the true trajectory.
- We calculate **edge length error** per frame: we compare the length of each edge in the predicted cloth vs the ground truth cloth at that frame, and take the mean absolute difference. If the model perfectly preserves constraints like the simulator, this would be near zero. Larger values mean the cloth is either over-stretched or too rigid relative to ground truth.
- We output the FPS computed. For example, if we simulated 100 frames in 0.5 seconds, FPS = 200 FPS. Our HGNN should be quite fast; we expect potentially dozens to hundreds of FPS depending on model size and hardware.
- Finally, we plot the errors over time.

## Step 7: README – Using Latent Node States with Downstream Surface Decoders

HGNN-ClothDyn not only predicts cloth node motions, but its hierarchical GNN structure learns rich **latent representations** of the cloth’s state. These latent node states (the hidden features in the GNN) can be leveraged by downstream models – for example, a neural implicit surface decoder that adds fine wrinkle details or produces a continuous surface from the coarse simulation.

**Extracting latent states:** In our implementation, the latent state of each node could be the output of the GNN just before the final prediction. For instance, `x0_final` in the model is a latent feature vector per node encapsulating the cloth dynamics context (neighbor influences, etc.). If we modify `HGNNClothDyn.forward` to return `x0_final` alongside the output, we can retrieve these features. Alternatively, we can store them during the forward pass. For example:

```python
# Modify forward to optionally return latent features
class HGNNClothDyn(nn.Module):
    # ... [same as before]
    def forward(self, data_lv0, data_lv1, assign_idx, return_latent=False):
        # ... [perform computations up to x0_final as above]
        if return_latent:
            return output, x0_final
        else:
            return output

# During inference or extraction phase:
data_lv0 = state_to_data(current_state)  # prepare Data for current cloth state
data_lv1 = data_lv1_template.clone()
pred_delta, latent_feats = model(data_lv0, data_lv1, assign_idx, return_latent=True)
# latent_feats is a tensor of shape [N_nodes, hidden_dim] containing each node's latent state.
```

Now `latent_feats[i]` is the feature vector for node i after the hierarchical message passing – essentially encoding the state of that node in context of its neighbors and global cloth configuration.

**Using latent features with an implicit surface decoder:** Suppose we want to generate a high-resolution surface or fine details (like extra wrinkles or thickness) from the coarse cloth simulation. We can train a neural **implicit function** (or any decoder) that takes these latent features as conditioning.

One common approach is to use a coordinate-based MLP (like those used in NeRF or DeepSDF) that, given a spatial position and some latent code, outputs whether that position lies on the cloth surface or outputs a displacement from a coarse surface. In our cloth context, a simple idea is:

- Use the barycentric coordinates or nearest neighbor interpolation to associate any 3D query point on the cloth surface with the latent features of nearby simulation nodes.
- Feed the query (in a local coordinate system) and the interpolated latent into an MLP that outputs, say, a height offset (for extra wrinkles) or a signed distance (to represent the cloth surface implicitly).

For example, if we have a coarse cloth mesh with nodes and we want a finer surface, we can do:

```python
# Pseudocode for using latent features in an implicit decoder
latent_feats = latent_feats.cpu().numpy()  # get latent features for each node (if not already numpy)
# Assume we have a function get_barycentric_coords(point) that finds which triangle of the coarse mesh the point projects to and returns (tri_index, w1, w2, w3).
point = np.array([x, y, z])  # some query point in 3D space near the cloth
tri_index, (w1, w2, w3) = get_barycentric_coords(point, coarse_mesh)
vi, vj, vk = coarse_mesh.triangles[tri_index]  # indices of the triangle's vertices (which correspond to our nodes)
# Fetch corresponding latent vectors:
hi, hj, hk = latent_feats[vi], latent_feats[vj], latent_feats[vk]
# Barycentric interpolate the latent feature for the query point:
h_point = w1*hi + w2*hj + w3*hk  # interpolated latent vector at query
# Also construct positional features (e.g., point's coordinates relative to the triangle plane or one vertex)
p_rel = point - vertices_coarse[vi]  # relative position to one vertex (or we could use (u,v) barycentric coords as input)
# Combine features and feed to implicit decoder:
input_feat = np.concatenate([h_point, p_rel])
# Example decoder usage:
surface_offset = decoder_model.predict(input_feat)
```

In this snippet:

- `h_point` is the latent feature at the query location, found by interpolating the node latents of the triangle containing the query. This ensures spatially smooth conditioning.
- `p_rel` (or one could use 2D barycentric coordinates `(u,v)`) provides the MLP with the query’s location relative to the cloth patch.
- `decoder_model` could be a small neural network that outputs something like a scalar displacement (which can add detail to the base geometry) or a binary value indicating if the point is inside the cloth surface (for an implicit surface representation).

**Usage example:** Imagine we want to increase the resolution of simulation for rendering. We simulate a coarse cloth with HGNN-ClothDyn (say 100 nodes) and get latent states for those 100 nodes. We train an implicit decoder that takes these 100 latents and can generate a dense mesh. For each pixel or for each vertex of a refined grid, we do as above to query the decoder. The decoder might output a refined vertex position that aligns with how the cloth would look if it had more vertices (adding wrinkles that the coarse sim couldn’t directly produce). Because the decoder has access to the latent dynamics (like where stress is high, where cloth is folding), it can place wrinkles or bulges in the right areas.

We can also use latent states for tasks like **style transfer or editing**: e.g., if one has latent vectors, one could potentially tweak them or feed them into another network to change the cloth’s appearance (analogous to how autoencoder latents are manipulated). But in the context of surface decoding, the latent essentially acts as a **conditioning input** that tells the implicit surface model “what is the cloth’s state here.”

**Code snippet for decoder network definition (for clarity):**

```python
import torch.nn as nn

class ClothSurfaceDecoder(nn.Module):
    def __init__(self, latent_dim, hidden_dim=64):
        super().__init__()
        # A simple MLP
        self.mlp = nn.Sequential(
            nn.Linear(latent_dim + 3, hidden_dim), nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim), nn.ReLU(),
            nn.Linear(hidden_dim, 1)  # output a scalar, e.g., offset or SDF value
        )
    def forward(self, latent, p_rel):
        # latent: [latent_dim], p_rel: [3] (x,y,z relative or other encoding)
        inp = torch.cat([latent, p_rel], dim=-1)
        return self.mlp(inp)
```

This `ClothSurfaceDecoder` takes a concatenation of a latent vector and a 3D coordinate (relative position) and outputs a scalar (for instance, a height offset). In use, one would pass `h_point` (latent for that query) and something like `p_rel` into it. One could modify this to output a 3D offset (by having 3 outputs) if we want to directly predict a position correction.

**Practical example:** Suppose our cloth simulation is too coarse to capture small wrinkles. We could simulate coarse, then use the decoder on a finer grid of points on each triangle to generate a subdivided mesh with wrinkles. Each point’s displacement is predicted by the network conditioned on the simulation’s latent. This way, the **latent node states act as a bridge** between the simulation and the high-frequency detail model.

In summary, to use latent states with downstream decoders:

1. **Extract latents** – run HGNN-ClothDyn on your cloth state and retrieve per-node latent vectors (modify the model to output them or use hooks).
2. **Provide mapping** – for any spatial query on the cloth, determine how to get the relevant latent(s) (via nearest nodes, barycentric in a triangle, etc.).
3. **Decode** – input the latent (or interpolated latents) plus positional info into your implicit function to get a surface property (offset, normal, occupancy).
4. **Reconstruct surface** – aggregate the decoder outputs (e.g., displace a base mesh or sample an implicit surface with Marching Cubes if using SDF).

By following these steps, one can **reconstruct high-resolution cloth surfaces** driven by the efficient HGNN-ClothDyn simulation. This two-stage approach (fast physics surrogate + neural renderer) is powerful: the simulator provides physically plausible global motion and constraints, while the decoder injects realistic fine detail, all in a learned, end-to-end manner.

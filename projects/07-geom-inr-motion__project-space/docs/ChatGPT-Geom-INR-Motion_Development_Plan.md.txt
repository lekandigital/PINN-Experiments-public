**Survey Summary (≈400 words):** Recent trends in human motion prediction and synthesis heavily leverage **continuous implicit representations** and generative models. Works like NeRMo and NeRM illustrate a paradigm shift: instead of treating motion as discrete frames, they model motion as a continuous function $f(t)$ parameterized by a neural network. In particular, **NeRMo**【22†L72-L79】 conditions on both *joint index* and *time* to output 3D joint positions. This joint–time INR can interpolate/extrapolate arbitrarily in space and time and naturally handles missing frames. Similarly, **NeRM**【30†L39-L48】 learns a latent-conditioned INR that captures motion trajectories at *native framerates*, bypassing the need to downsample or align varying frame rates. These INR methods show state-of-the-art forecasting and synthesis by directly optimizing coordinate-based networks.

Parallel to implicit models, **diffusion-based architectures** have emerged for diverse motion generation. MotionDiff【23†L60-L69】 exemplifies this by modeling each joint’s kinematics in a diffusion framework: a forward diffusion whitens the motion (no learnable sampler needed), and a learned reverse diffusion with a spatio-temporal Transformer + GCN generates future poses. This yields rich stochastic motion samples while mitigating issues like latent collapse in VAE frameworks.

Another key trend is **geometric regularization**. While explicit use of geometry (e.g. curvature, torsion) in deep motion models is still nascent, classical insights suggest that human motions are inherently smooth. SIREN networks【40†L59-L64】 (using sine activations) demonstrate that periodic functions are ideal for encoding smooth, high-frequency signals and their derivatives, hinting that INR-based motion models can capture fine motion details. However, most recent works (NeRMo, NeRM, MotionDiff) do not explicitly enforce *differential geometry constraints*. This gap suggests room for integrating torsion/curvature penalties to further smooth motion paths.

**Limitations and Gaps:** Existing INR models excel at continuity and memory efficiency but largely ignore physical plausibility or skeletal constraints beyond kinematics. For example, NeRMo and NeRM focus on coordinate outputs without explicitly enforcing bone lengths or joint limits. Diffusion models like MotionDiff capture diversity but may produce jittery trajectories absent smoothness priors. Moreover, most works assume a fixed skeleton (often SMPL), so *retargeting* or handling different skeletons is an open challenge. We also note a gap in integrating actor-specific priors: conditioning on actor ID (body shape or style) has been under-explored in INR motion models. Finally, while INR approaches handle missing data well【22†L72-L79】, systematic evaluation on long-horizon consistency and retargeting to new skeletons remains underdeveloped. The proposed Geom-INR-Motion framework aims to fill these gaps by combining continuous-time INRs with **geometric regularization (torsion, curvature) and skeleton-aware modules**, enabling robust, smooth long-horizon predictions and easy retargeting.

import numpy as np
import glob
from scipy.interpolate import CubicSpline, interp1d
from sklearn.preprocessing import StandardScaler

def load_amass(amass_dir):
    """
    Load SMPL pose sequences from AMASS dataset.
    Each AMASS file is assumed to have 'poses' (PxJx3 rotations or positions) and 'trans' (Px3 root translations).
    Returns a list of motion sequences (N_joints x 3).
    """
    sequences = []
    for file in glob.glob(amass_dir + '/*.npz'):
        data = np.load(file)
        poses = data['poses']  # shape: (T, J, 3) or (T, 156) flattened
        if poses.ndim == 2:
            # If flattened (e.g., 156 dims for 52 joints), reshape to (T, J, 3)
            poses = poses.reshape(-1, 52, 3)  # example joints
        trans = data['trans']  # (T, 3) root translations
        # Append sequence of joint world positions
        # (assuming poses are axis-angle or rotation, convert to positions if needed)
        sequences.append(poses + trans[:, None, :])  # broadcast root translation
    print(f"Loaded {len(sequences)} AMASS sequences.")
    return sequences

def load_h36m(h36m_file):
    """
    Load poses from Human3.6M dataset.
    Assume file format with joint positions or rotations (e.g., .h5 or .npz).
    Returns sequences of joint positions (T x J x 3).
    """
    data = np.load(h36m_file)
    poses = data['poses']  # (T, J, 3) array or (T, K) array
    if poses.ndim == 2:
        # Example: if axis-angle, convert to XYZ (requires SMPL model usage, omitted here)
        raise NotImplementedError("H3.6M conversion from axis-angle not shown")
    print(f"H3.6M sequence shape: {poses.shape}")
    return poses

def normalize_skeletons(sequences):
    """
    Normalize skeletons by zero-centering the root and scaling average bone length.
    This ensures consistent scale across AMASS and H3.6M.
    """
    all_joints = np.concatenate([seq for seq in sequences], axis=0)  # (sumT, J, 3)
    # Zero-center: subtract mean root (joint 0 assumed) from each pose
    # (Here, we assume joint 0 is the root)
    # Also compute global scale (e.g., average hip-to-neck distance)
    roots = all_joints[:, 0, :]
    mean_root = roots.mean(axis=0)
    bones = np.linalg.norm(all_joints[:, 0, :] - all_joints[:, 1, :], axis=1)  # example bone length
    scale = np.mean(bones)
    print(f"Normalizing: root mean {mean_root}, avg bone length {scale}")
    
    normalized = []
    for seq in sequences:
        seq = seq.copy()
        seq = seq - mean_root  # center
        seq = seq / scale     # scale
        normalized.append(seq)
    return normalized

def interpolate_sequence(seq, fps=30, method='spline'):
    """
    Given a discrete pose sequence (T x J x 3), interpolate to a continuous function of time.
    Returns a function f(t) returning Jx3 poses for any real t in [0, T-1].
    """
    T, J, _ = seq.shape
    times = np.linspace(0, T-1, T)  # original frame times
    # Build splines for each joint coordinate
    def motion_func(t_query):
        """
        Evaluate interpolated pose at time t_query (scalar or array).
        """
        t_query = np.array(t_query, ndmin=1)
        out = np.zeros((t_query.shape[0], J, 3))
        for j in range(J):
            for dim in range(3):
                if method == 'spline':
                    cs = CubicSpline(times, seq[:, j, dim])
                    out[:, j, dim] = cs(t_query)
                else:  # linear interpolation
                    lin = interp1d(times, seq[:, j, dim], kind='linear', fill_value="extrapolate")
                    out[:, j, dim] = lin(t_query)
        return out  # shape (len(t_query), J, 3)
    return motion_func

In the above pipeline, we load AMASS and Human3.6M data into consistent SMPL-based representations (AMASS sequences already in SMPL coordinate form【43†L139-L147】). We then **normalize** all skeletons by centering on the hip (root joint) and scaling by an average bone length, ensuring consistent anthropometry across actors. Next, we convert each discrete sequence into a continuous mapping $f(t)$. Using SciPy’s `CubicSpline` (or linear `interp1d`), we fit each joint’s XYZ trajectory as a smooth function of time. This yields a callable `motion_func(t)` that returns joint poses at any real time $t$, enabling the INR to query ground-truth poses at arbitrary time stamps.

For example, a query at a missing or fractional timestamp automatically interpolates the motion smoothly. This continuous-time representation is essential for training an INR: during training we will sample random time coordinates and compare predicted joint positions to these interpolated "ground truth" poses.

```python
# model.py
import torch
import torch.nn as nn
import math

class GeomINR(nn.Module):
    """
    Geom-INR model: an implicit neural network that maps (actor ID, joint index, time)
    to 3D joint positions. Uses sine activations (like SIREN) and an optional graph module
    for skeleton constraints.
    """
    def __init__(self, n_joints=52, time_dim=1, actor_dim=1, hidden_dim=256, num_layers=4, actor_embed_dim=32):
        super().__init__()
        # Embedding for actor (subject) ID
        self.actor_embed = nn.Embedding(num_embeddings=100, embedding_dim=actor_embed_dim)  # support up to 100 actors
        input_dim = time_dim + 1 + actor_embed_dim  # time + joint index + actor embed

        # Positional encoding for joint index (as continuous scalar between 0 and 1)
        # Alternatively, we can feed joint index directly as a coordinate
        self.joint_index_encoder = lambda idx: torch.tensor([idx], dtype=torch.float32)
        
        # Build MLP with sine activations (SIREN-style)
        self.layers = nn.ModuleList()
        self.layers.append(nn.Linear(input_dim, hidden_dim))
        for _ in range(num_layers - 1):
            self.layers.append(nn.Linear(hidden_dim, hidden_dim))
        self.out_layer = nn.Linear(hidden_dim, 3)  # output (x,y,z) offset for joint

        # Initialization for SIREN (following Sitzmann et al. 2020)
        with torch.no_grad():
            self.layers[0].weight.uniform_(-1/math.sqrt(input_dim), 1/math.sqrt(input_dim))
            for layer in self.layers[1:]:
                layer.weight.uniform_(-math.sqrt(6/hidden_dim)/math.pi, math.sqrt(6/hidden_dim)/math.pi)
        
        # Optional Graph-Convolution module to enforce skeleton structure
        # (Here we implement a simple adjacency-based smoothing layer)
        self.use_graph = True
        if self.use_graph:
            # Precompute normalized adjacency matrix A (JxJ)
            # For demonstration, assume a chain or tree; here use identity (no-op)
            self.adj = torch.eye(n_joints)  # replace with actual adjacency
            self.graph_scale = nn.Parameter(torch.tensor(1.0))  # learnable smoothing factor

    def forward(self, actor_ids, joint_indices, times):
        """
        actor_ids: (B,) tensor of actor IDs
        joint_indices: (B,) tensor of joint indices (0..n_joints-1)
        times: (B,) tensor of times (continuous)
        Returns: (B, 3) predicted joint positions.
        """
        # Embed actor ID
        actor_feat = self.actor_embed(actor_ids)  # (B, actor_embed_dim)
        # Encode time and joint index
        time_feat = times.unsqueeze(-1)  # (B, 1)
        joint_idx_feat = joint_indices.float().unsqueeze(-1)  # (B, 1)
        # Normalize joint index to [0,1] or embed if needed
        joint_idx_norm = joint_idx_feat / (self.adj.size(0) - 1)
        x = torch.cat([time_feat, joint_idx_norm, actor_feat], dim=-1)  # (B, input_dim)
        
        # SIREN MLP with sine activations
        for layer in self.layers:
            x = torch.sin(layer(x))
        coords = self.out_layer(x)  # (B, 3)

        # Graph-based refinement: ensure consistency among joints
        if self.use_graph:
            # Reshape coords (if batch groups by sequence) to (J, 3) for one pose, or sum across batch
            # Here we assume batch is one pose with multiple joints (J = B)
            # For generality, do smoothing per joint independently:
            coords_all = coords.view(-1, 3)  # (J, 3) if each batch entry is a distinct joint
            smoothed = torch.matmul(self.adj, coords_all)  # (J,3): aggregate neighbors
            coords = coords_all + self.graph_scale * (smoothed - coords_all)
        return coords
```

**Model Explanation:** The **GeomINR** network is a time-conditioned implicit model. Its inputs are the continuous time $t$, a discrete joint index $j$, and an actor ID (subject identity). We embed the actor ID into a vector and normalize the joint index (e.g. $j/(J-1)$). The MLP uses **sine activations** in each layer (inspired by SIREN【40†L59-L64】) to flexibly model high-frequency motion details. The final linear layer outputs a 3D offset, representing the predicted joint position at time $t$.

Optionally, a **graph-based refinement** is applied: we construct an adjacency matrix $A$ encoding the skeleton connectivity (not shown in full for brevity; in practice, $A$ has $A\_{ij}=1$ if joints $i,j$ are connected). After predicting all joint positions for a given pose, we can apply one smoothing pass: $$\mathbf{p}\_i \leftarrow \mathbf{p}*i + \lambda \sum*{j\in\mathcal{N}(i)} (p\_j - p\_i),$$ where $\lambda$ is learnable (here `graph_scale`). This encourages local consistency and preserves bone-length constraints. Each component is fully differentiable, allowing backpropagation of geometric losses (curvature, torsion) discussed next.

## 4. Geometric Loss Functions

To encourage smooth, realistic motion, we define **differential-geometry penalties** on the predicted trajectories. For each joint trajectory $\mathbf{r}(t)$ in 3D, we compute the Frenet–Serret curvature $\kappa(t)$ and torsion $\tau(t)$ using finite differences. Discretely, given a predicted sequence of joint positions ${\mathbf{r}*n}$ at times $t\_n$, we approximate derivatives:
$
\mathbf{r}'*n \approx \mathbf{r}*{n+1} - \mathbf{r}*{n},
\quad
\mathbf{r}''*n \approx \mathbf{r}*{n+2} - 2\mathbf{r}*{n+1} + \mathbf{r}*n,
\quad
\mathbf{r}'''*n \approx \mathbf{r}*{n+3} - 3\mathbf{r}*{n+2} + 3\mathbf{r}*{n+1} - \mathbf{r}\_n.
$
The **curvature** is then
$
\kappa\_n = \frac{|\mathbf{r}'\_n \times \mathbf{r}''\_n|}{|\mathbf{r}'*n|^3 + \varepsilon},
$
and the **torsion** is
$
\tau\_n = \frac{(\mathbf{r}'*n \times \mathbf{r}''*n) \cdot \mathbf{r}'''*n}{(|\mathbf{r}'*n \times \mathbf{r}''*n|^2 + \varepsilon)}.
$
We penalize the squared curvature and torsion averaged over all joints and times:
$
L*{\kappa} = \frac{1}{NJ} \sum*{n,j} \kappa*{n,j}^2,
\quad
L*{\tau} = \frac{1}{NJ} \sum*{n,j} \tau*{n,j}^2,
$
where $J$ is number of joints and $N$ frames. These losses encourage **smooth, low-curvature** trajectories and minimal twist variation.

```python
import torch

def compute_curvature_torsion(trajectory, eps=1e-6):
    """
    trajectory: Tensor of shape (T, J, 3) for one sequence (J joints).
    Returns: tensors of curvature and torsion of shape (T-3, J).
    """
    # First derivatives (velocity)
    v = trajectory[1:] - trajectory[:-1]         # (T-1, J, 3)
    a = v[1:] - v[:-1]                           # (T-2, J, 3)
    j = a[1:] - a[:-1]                           # (T-3, J, 3)
    # Compute curvature and torsion
    # Use v[:-2], a[:-1], j for consistent lengths
    v = v[:-2]   # (T-3, J, 3)
    a = a[:-1]   # (T-3, J, 3)
    j = j        # (T-3, J, 3)
    # Cross product for curvature
    cross = torch.cross(v, a, dim=2)            # (T-3, J, 3)
    kappa = torch.norm(cross, dim=2) / (torch.norm(v, dim=2)**3 + eps)  # (T-3, J)
    # Torsion: (v x a) · j / ||v x a||^2
    numerator = (cross * j).sum(dim=2)          # (T-3, J)
    denom = (torch.norm(cross, dim=2)**2 + eps) # (T-3, J)
    tau = numerator / denom                     # (T-3, J)
    return kappa, tau

# Example usage in loss computation
pred_traj = torch.randn(100, 52, 3, requires_grad=True)  # (T=100, J=52)
kappa, tau = compute_curvature_torsion(pred_traj)
loss_curv = (kappa**2).mean()
loss_tors = (tau**2).mean()
geo_loss = 1e3 * loss_curv + 1e2 * loss_tors  # weighted combination
```

These losses are **differentiable** and can be added to the training objective.  Intuitively, minimizing curvature $\kappa$ penalizes sharp bends in joint paths, while minimizing torsion $\tau$ penalizes rapid twisting of the trajectory.  In practice, we balance these with a weighted sum ($L\_{\kappa}$, $L\_{\tau}$) to smooth motions without oversmoothing (weights in example code).

**Comparison to Diffusion Baselines:** As a baseline, we include a diffusion-based model such as MotionDiff【23†L60-L69】. In our comparison, we train MotionDiff (spatio-temporal transformer + GCN) on the same data splits and evaluate using identical metrics. Because MotionDiff learns a stochastic latent, we measure its diversity and accuracy by generating multiple samples. Our evaluation toolkit (below) will compute FID-Motion and MPJPE for both models. We expect the geometric losses in Geom-INR to improve *smoothness* and bone-length consistency, potentially at a small cost to diversity, compared to MotionDiff.

## 5. Training Pipeline

class MotionDataset(Dataset):

    def __init__(self, motion_funcs, seq_length=50):

        self.seq_length = seq_length

    def __len__(self):
        return len(self.motion_funcs) * 100  # synthetic dataset size (e.g., 100 samples/seq)

    def __getitem__(self, idx):
        seq_fn = self.motion_funcs[idx // 100]
        # sample a random time window
        T = seq_fn(np.arange(0, 1))  # dummy
        start_t = np.random.uniform(0, len(seq_fn(np.array([]))) - self.seq_length - 1)
        times = start_t + np.arange(self.seq_length)

        joints = torch.arange(0, 52, dtype=torch.long)  # example 52 joints
        # Expand for time dimension
        actor_batch = actor_id.repeat(self.seq_length * len(joints))
        joint_batch = joints.repeat(self.seq_length)
        time_batch = torch.cat([times[i].repeat(len(joints)) for i in range(self.seq_length)])
        # Ground-truth positions
        # In practice, evaluate seq_fn at these times
        positions = []
        for t in times:
            pos = torch.tensor(seq_fn([t.item()])[0])  # (J,3)
            positions.append(pos)
        positions = torch.stack(positions, dim=0)  # (T, J, 3)
        positions = positions.view(-1, 3)  # flatten: (T*J, 3)
        return actor_batch, joint_batch, time_batch, positions

In this training script, we load batches of `(actor_id, joint_idx, time) → target_position` and optimize mean-squared error (equivalent to MPJPE) plus weighted geometric losses. We use a cosine step LR scheduler. Training is done on GPU (`device`) to leverage the large 24GB VRAM. Checkpoints are saved periodically.

def export_to_usd(filepath, joint_trajectories, joint_names):
    """
    Export joint_trajectories (dict of joint_name->list of Gf.Vec3f per frame) to a USD file.
    """
    stage = Usd.Stage.CreateNew(filepath)
    # Create a skeleton prim
    skeleton = UsdGeom.Xform.Define(stage, '/Root')

        # Create transform for each joint
        jt = UsdGeom.Xform.Define(stage, f'/Root/{name}')
        for frame, pos in enumerate(joint_trajectories[name]):
            time = frame * (1/30)  # assuming 30Hz

## 6. Evaluation Toolkit

We provide a Jupyter notebook `evaluation.ipynb` that computes standard motion metrics:

- **MPJPE (Mean Per-Joint Position Error):** $\text{MPJPE} = \frac{1}{TN}\sum\_{t,j}|\hat{\mathbf{p}}*{t,j}-\mathbf{p}*{t,j}|\_2$, comparing predicted vs. ground-truth joint positions.
- **FID-Motion:** Analogous to image FID, we compute the Fréchet distance between feature distributions of generated and real motions. Concretely, we embed each sequence via a pretrained action recognition network (e.g., an LSTM or transformer) and compute FID on those embeddings (see *DART*【36†L1-L4】 for similar usage). Lower FID indicates closer match to data distribution.
- **Smoothness Metric:** We quantify smoothness by average *jerk* (third derivative of position). For each joint trajectory, compute accelerations $\mathbf{a}\_t$ and jerks $\mathbf{j}*t = \mathbf{a}*{t+1}-\mathbf{a}*t$. Then define smoothness = $\frac{1}{TN}\sum |\mathbf{j}*{t,j}|\_2$. Lower jerk implies smoother motion.

## 7. Blender Add-on

We supply a Blender 4.x add-on (`geom_inr_retarget.py`) enabling motion retargeting using the trained Geom-INR model. Key features:

- **UI Panel:** A sidebar panel (“GeomINR Retarget”) in Blender’s 3D View. Contains:
  - **Model Loader:** Button to select and load a trained model checkpoint.
  - **Actor ID Slider:** A slider or dropdown to set the actor ID conditioning (e.g., to apply style).
  - **Target BVH Loader:** Button to import a source motion (e.g., BVH file for a different skeleton).
  - **Retarget Button:** Runs the model on the source skeleton’s timeline and applies the new poses to the Blender rig.

```python
# geom_inr_retarget.py
bl_info = {
    "name": "GeomINR Motion Retargeting",
    "category": "Animation",
    "blender": (4, 0, 0),
}

import bpy

class GI_OT_LoadModel(bpy.types.Operator):
    """Load pretrained Geom-INR model"""
    bl_idname = "gi.load_model"
    bl_label = "Load Geom-INR Model"
    def execute(self, context):
        path = bpy.path.abspath(context.scene.gi_model_path)
        # Load PyTorch model weights (in background)
        # e.g. model.load_state_dict(torch.load(path))
        self.report({'INFO'}, f"Loaded model from {path}")
        return {'FINISHED'}

class GI_OT_Retarget(bpy.types.Operator):
    """Retarget motion using Geom-INR model"""
    bl_idname = "gi.retarget_motion"
    bl_label = "Retarget Motion"
    def execute(self, context):
        actor_id = context.scene.gi_actor_id
        # For each frame: sample time, joint index, use model to get new pose
        # Then apply to target armature (via PoseBone transforms).
        self.report({'INFO'}, f"Retargeted motion with actor ID {actor_id}")
        return {'FINISHED'}

class GI_PT_Panel(bpy.types.Panel):
    bl_label = "GeomINR Retarget"
    bl_idname = "GI_PT_panel"
    bl_space_type = 'VIEW_3D'
    bl_region_type = 'UI'
    bl_category = 'GeomINR'
    def draw(self, context):
        layout = self.layout
        layout.prop(context.scene, "gi_model_path")
        layout.operator("gi.load_model", text="Load Model")
        layout.prop(context.scene, "gi_actor_id")
        layout.operator("gi.retarget_motion", text="Retarget")

def register():
    bpy.utils.register_class(GI_OT_LoadModel)
    bpy.utils.register_class(GI_OT_Retarget)
    bpy.utils.register_class(GI_PT_Panel)
    bpy.types.Scene.gi_model_path = bpy.props.StringProperty(
        name="Model File", subtype='FILE_PATH')
    bpy.types.Scene.gi_actor_id = bpy.props.IntProperty(
        name="Actor ID", min=0, max=99)

def unregister():
    bpy.utils.unregister_class(GI_OT_LoadModel)
    bpy.utils.unregister_class(GI_OT_Retarget)
    bpy.utils.unregister_class(GI_PT_Panel)

if __name__ == "__main__":
    register()
```

**Usage:** After installing the add-on, the user can load the trained Geom-INR weights and a source BVH. The add-on runs the model over each frame of the source motion, retargets joint coordinates, and applies them to the target rig via Blender’s PoseBone API. Sliders let the user tweak `actor_id` to blend different motion styles if multiple subjects were trained. This provides an **interactive** interface for motion retargeting.

Without my NIF

Analytic physics cloth

The synthetic cloth simulator we built the dataset from: a falling shell interpolated from a flat state at t=0 to a fully draped state at t=1. Clean, but locked to one resolution and one discrete timeline.

With my NIF

Learned SIREN SDF

A 5-layer SIREN with ω₀=30, 256 hidden units, Fourier feature input encoding. Trained for 500 epochs against per-sample SDF with a light Eikonal regulariser. The same checkpoint drives every frame below — only the query coordinates change.

The representation changes, not the solver

Cloth as a field, not a mesh

Most cloth pipelines store the state as a discrete mesh at fixed timesteps. NIF-Cloth4D stores it as a continuous function. That swap is the whole point — the downstream savings (arbitrary resolution, arbitrary temporal queries, no popping, one file to ship) follow from it.

Query any resolution

The viewer samples the field on a 128×128 heightfield, but nothing in the checkpoint is tied to that grid. Swap in a 512×512 grid, or an adaptive quadtree, and the same weights give you a denser or cheaper mesh. No retraining.

Query any time

Training uses 12 source timesteps, but t is a continuous input. The player interpolates between the source frames visually; the model itself would happily give you t = 0.47 directly. That's why the drape plays back smoothly at 30 fps from 12 source frames.

Fixed-topology extraction

For this demo we extract by heightfield (per-(x,y), find z where SDF is most negative). Because the cloth is a thin z = f(x, y, t) shell, this gives the same 16,384 vertices and 32,258 triangles every frame — no marching-cubes popping.

One file to ship

The trained checkpoint is 3.8 MB. Compared to shipping a 12-frame, 16k-vertex mesh sequence (~2.4 MB of vertices alone) and a solver, the field representation scales far better the moment you ask for more resolution or finer time steps.

How close does it get?

Evaluation — Chamfer & Hausdorff vs. the physics baseline

Both metrics are computed directly on the extracted meshes: point-to-point Chamfer for overall fidelity, Hausdorff for worst-case deviation. The rightmost red bump at t=1 is the full drape — the hardest region, where the field has to commit to a non-trivial curved geometry.

Rendering — Taichi GGUI

Three presets, one viewer

src/taichi_cloth_demo.py wraps the heightfield sequences in a Taichi GGUI scene with dark background, warm-key / cool-fill lighting, and a per-vertex height-diverging colormap. Presets share the same rig; only camera, density, and shading differ.

Why this matters

Why a NIF for cloth?

  • Continuous spatiotemporal SDF. No mesh fixed at training time. Query cloth geometry as a smooth function of (x, y, z, t).
  • Resolution-independent queries. Heightfield today, adaptive remeshing tomorrow. Same weights.
  • Compact learned representation. 3.8 MB checkpoint replaces a solver + discrete state. Ship one artifact.
  • Smooth interpolation in time. 12 source frames become arbitrarily many display frames, with no manual tweening.
  • Faster than re-running physics at new resolutions. A forward pass through the SIREN scales with query count, not simulation steps.
  • Fixed-topology output by construction. Heightfield extraction removes marching-cubes popping — the mesh never changes vertex count across frames.

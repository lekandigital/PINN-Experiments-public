## 2. SPH Simulation Dataset Generation

To train SurfPINN, we use DualSPHysics (an open-source SPH solver) to generate labeled data. The following Python script outlines how to run 2D/3D SPH simulations, interpolate free-surface heights onto a regular grid, and save both Eulerian and Lagrangian data in HDF5 format. Comments explain each step:

```python
import numpy as np
import h5py
import subprocess

# Example function to run a DualSPHysics simulation case
def run_dual_sph(case_file):
    """
    Run a DualSPHysics simulation given an input XML case definition.
    Outputs particle snapshots (positions, velocities, etc.) over time.
    """
    # Invoke DualSPHysics via command line (ensure DualSPH is installed)
    subprocess.run(['DualSPHysics', case_file], check=True)

# Load particle data and build ground truth dataset
def process_sph_data(particle_file, grid_dims):
    """
    Read particle output, interpolate height field on a uniform Eulerian grid,
    and assemble Lagrangian particle trajectories.
    """
    # Load particle positions (x,y,z) and possibly velocity from output files
    data = np.loadtxt(particle_file)  # shape (N_particles, ...)

    # Extract particle coordinates (example for 3D; in 2D, z=0 for free surface)
    x = data[:,0]; y = data[:,1]; z = data[:,2]

    # Determine free surface height: take max z for each (i,j) cell
    # Define Eulerian grid limits
    nx, ny, nz = grid_dims  # e.g. (100,100,50)
    xgrid = np.linspace(x.min(), x.max(), nx)
    ygrid = np.linspace(y.min(), y.max(), ny)
    # Create grid of height values (initialize to base level)
    height = np.zeros((ny, nx))
    dx = xgrid[1] - xgrid[0]; dy = ygrid[1] - ygrid[0]
    # Bin particles into grid cells and record max height
    for xi, yi, zi in zip(x, y, z):
        i = int((xi - xgrid[0]) / dx)
        j = int((yi - ygrid[0]) / dy)
        if 0 <= i < nx and 0 <= j < ny:
            height[j,i] = max(height[j,i], zi)
    # Create Lagrangian data: e.g., initial and final positions for tracked surface particles
    # (Here as example, use all particles; in practice select surface subset)
    lagrangian = np.stack([x, y, z], axis=1)  # shape (N,3)

    return height, lagrangian

# Example usage:
run_dual_sph('dam_break_case.xml')
height_field, particle_positions = process_sph_data('particles_output.txt', grid_dims=(100,100,1))

# Save data to HDF5
with h5py.File('sph_dataset.h5', 'w') as f:
    f.create_dataset('height', data=height_field.astype(np.float32))
    f.create_dataset('particles', data=particle_positions.astype(np.float32))
```

- **Simulation setup:** Users should define DualSPHysics XML case files for 2D or 3D free-surface flows (e.g., dam break, wave tank). The `run_dual_sph` function calls the solver.
- **Eulerian interpolation:** We bin particle heights into a fixed grid to produce an Eulerian height field. This captures the free-surface profile on a regular mesh.
- **Lagrangian data:** We save particle positions (and velocities if needed) over time. For surface particles, record trajectories.
- **Validation:** Check mass conservation (total particle volume) and energy trends. Ensure the simulated free surface matches expectations (e.g. known analytical solution or previous results). Consistency between SPH and Eulerian fields can be cross-verified by integrating height vs. particle volume.

This yields HDF5 tensors (`height` and `particles`) as ground truth for training SurfPINN.

## 3. Dual-Branch Network (JAX/Haiku)

We implement SurfPINN with two branches: an Eulerian 3D CNN predicting height fields, and a Lagrangian MLP for particle paths, joined by a shared latent representation. The code below uses [JAX](https://jax.readthedocs.io/) and [Haiku](https://github.com/deepmind/dm-haiku) to define the model and physics loss functions. Comments explain inputs/outputs.

```python
import haiku as hk
import jax
import jax.numpy as jnp

class SurfPINN(hk.Module):
    def __init__(self, latent_dim=128, name=None):
        super().__init__(name=name)
        # Eulerian branch: 3D CNN for height field (input: xyz grid coords)
        self.eul_enc = hk.Sequential([
            hk.Conv3D(32, kernel_shape=3, stride=1, padding='SAME'),
            jax.nn.relu,
            hk.Conv3D(64, 3, 1, 'SAME'), jax.nn.relu,
            hk.Conv3D(latent_dim, 3, 1, 'SAME'),
        ])
        # Lagrangian branch: MLP for particle positions
        self.lagr_enc = hk.Sequential([
            hk.nets.MLP([64, 64, latent_dim], activate_final=False)
        ])
        # Decoder (shared to produce outputs if needed)
        self.decoder = hk.Sequential([
            hk.nets.MLP([64, 64, 3], activate_final=False)  # outputs e.g. velocity/pitch
        ])

    def __call__(self, grid_coords, particle_pos):
        """
        Args:
          grid_coords: array of shape (Nx, Ny, Nz, 3) - coordinates for Eulerian grid points
          particle_pos: array of shape (N_particles, 3) - Lagrangian positions
        Returns:
          height_pred: predicted height field on grid (Nx, Ny, Nz, 1)
          velocity_pred: predicted velocities for particles (N_particles, 3)
        """
        # Eulerian encoding of grid (batch + flatten)
        batch_grid = grid_coords[None, ...]  # add batch dim
        z_eul = self.eul_enc(batch_grid)   # (1, Nx, Ny, Nz, latent_dim)
        z_eul = jnp.squeeze(z_eul, axis=0) # (Nx, Ny, Nz, latent_dim)
        # Decoder to height: treat latent as feature map and decode scalar height
        height_pred = hk.Conv3D(1, 1, 1, 'SAME')(z_eul)[None, ...]  # (1,Nx,Ny,Nz,1)
        height_pred = jnp.squeeze(height_pred, axis=0)  # (Nx, Ny, Nz, 1)

        # Lagrangian encoding and decoding
        z_lag = self.lagr_enc(particle_pos)       # (N_particles, latent_dim)
        velocity_pred = self.decoder(z_lag)       # (N_particles, 3)

        return height_pred, velocity_pred

def physics_loss(eulerian_vars, lagrangian_vars):
    """
    Define physics-informed loss:
      - Navier–Stokes residuals on Eulerian grid (momentum + continuity)
      - Kinematic condition for free surface and/or incompressibility at particle points
    """
    # Unpack predictions and (true) fields
    height_pred, vel_pred = eulerian_vars
    _, _ = lagrangian_vars  # placeholder for true particle data if needed

    # Compute spatial derivatives via autodiff for NS equations
    # Example: continuity residual (∇·u = 0) on grid (approx by finite differences or conv)
    # Example: momentum residuals using grads of vel_pred and pressure (if modeled)
    # For brevity, pseudo-code:
    div_u = jnp.sum(jax.grad(lambda y: vel_pred)(jnp.array([1.0,0,0])))  # placeholder
    momentum_res = vel_pred  # placeholder

    # Combine residuals into loss
    loss_ns = jnp.mean(div_u**2 + momentum_res**2)
    # Kinematic free-surface loss: particles on surface should move with velocity normal to surface gradient
    # e.g., (dz/dt - w)² where w is vertical velocity
    loss_free = jnp.mean((lagrangian_vars - ...) ** 2)  # placeholder

    return loss_ns + loss_free

# Transform to Haiku model
surf_model = hk.transform(lambda x, p: SurfPINN()(x, p))
```

- **Network structure:** The Eulerian branch (`eul_enc`) encodes the 3D height-field grid into a latent tensor, then decodes it to predict heights. The Lagrangian branch (`lagr_enc` + `decoder`) maps particle positions to predicted velocities (or displacements).
- **Shared latent space:** Both branches encode into vectors of dimension `latent_dim`. If desired, one can concatenate or otherwise fuse `z_eul` and `z_lag` for joint reasoning, but here they share dimension and could be jointly trained.
- **Physics loss:** We define PINN losses using **JAX autodiff**. For example, continuity (`∇·u=0`) and momentum (Navier–Stokes residuals) on the Eulerian grid can be computed by differentiating the predicted velocities. On the free surface, a kinematic condition (e.g. height evolution matching vertical velocities) can be enforced. Loss terms like `L_NS = mean(residual²)` and `L_kin = mean((dz/dt - w)²)` are summed to form the physics loss.

This modular setup allows autopmation of gradients and flexible experimentation with loss terms.

## 4. Geometry-Based Curvature Loss

To improve surface realism, we add a mean-curvature smoothing loss on the height field. Mean curvature of a graph $z=h(x,y)$ can be approximated by finite differences:

$
\kappa = \nabla \cdot \frac{\nabla h}{\sqrt{1+|\nabla h|^2}}.
$

Below is a JAX function that computes mean curvature on a 2D height grid and a corresponding loss:

```python
import jax.numpy as jnp

def mean_curvature_loss(height):
    """
    Compute mean curvature (squared) of a height field and return loss.
    Height shape: (Nx, Ny, 1) or similar.
    """
    # Assume height shape (N, M)
    h = jnp.squeeze(height, axis=-1)  # (Nx, Ny)
    # Compute gradients
    h_x = (h[:,2:] - h[:,:-2]) / 2.0     # central diff in x
    h_y = (h[2:,:] - h[:-2,:]) / 2.0     # central diff in y
    # Pad to original shape (zero gradient at boundaries)
    h_x = jnp.pad(h_x, ((0,0),(1,1)), constant_values=0)
    h_y = jnp.pad(h_y, ((1,1),(0,0)), constant_values=0)

    # Second derivatives
    h_xx = (h[:,2:] - 2*h[:,1:-1] + h[:,:-2])
    h_yy = (h[2:,:] - 2*h[1:-1,:] + h[:-2,:])
    h_xy = (h[1:-1,2:] - h[1:-1,:-2] - h[:-2,1:-1] + h[2:,1:-1]) / 4.0

    # Pad second derivs
    h_xx = jnp.pad(h_xx, ((0,0),(1,1)))
    h_yy = jnp.pad(h_yy, ((1,1),(0,0)))
    h_xy = jnp.pad(h_xy, ((1,1),(1,1)))

    # Compute curvature κ with formula for graph surfaces
    grad_sq = 1 + h_x**2 + h_y**2
    num = (1 + h_y**2)*h_xx - 2*h_x*h_y*h_xy + (1 + h_x**2)*h_yy
    denom = grad_sq ** 1.5
    kappa = num / (denom + 1e-8)
    
    # Mean-curvature smoothing loss (e.g., L2 norm of curvature)
    loss_curv = jnp.mean(kappa**2)
    return loss_curv

# Example usage: add to total loss
# height_pred is model output (Nx,Ny,1)
L_curv = mean_curvature_loss(height_pred)
total_loss = physics_loss(...) + 0.1 * L_curv
```

- **Explanation:** We compute finite differences to get $h\_x, h\_y, h\_{xx}, h\_{yy}, h\_{xy}$. Then apply the curvature formula. The loss is the mean-squared curvature, which penalizes sharp bends.
- **Effect:** Minimizing this loss encourages the height field to be smoother and more physically plausible (avoiding spurious wrinkles). In practice, one should weight this term so as not to override physical accuracy.
- **Validation:** Visualize curvature on example surfaces (e.g. before/after training). Check that adding the curvature loss reduces artifacts without blurring important features. This can be done by plotting height fields or curvature heatmaps using Matplotlib or PyVista.

  ```python
      grads = jax.lax.pmean(grads, axis_name='batch')
      new_params = apply_updates(params, grads)
      return new_params
  ```
  - Use `jax.device_count()` to replicate `params` to all devices.
  - On TPUs/GPU clusters (e.g. GKE with TPU), use `jax.distributed.initialize()` and `jax.pmap` similarly.
- **Additional tips:** Enable XLA `--xla_gpu_autotune_level=2` for kernel tuning. Use `jax.profiler` to monitor memory. Allocate variables in 16-bit where gradients are large (weights) and keep loss accumulation in 32-bit if needed.

By using mixed precision and data parallelism, SurfPINN can efficiently use a 3090 and scale out to multiple GPUs/TPUs.

## 6. Visualization of Predictions

We create a Jupyter notebook to visualize both the Eulerian surface and Lagrangian trajectories, and to compute evaluation metrics.

**Key steps and code:**

1. **Load predictions and ground truth** from HDF5:
   ```python
   import h5py
   import pyvista as pv
   import numpy as np

   data = h5py.File('predictions.h5', 'r')
   height_pred = data['height_pred'][...]  # shape (Nx,Ny)
   height_true = data['height_gt'][...]
   pts_pred = data['particles_pred'][...]  # (N_pred,3)
   pts_true = data['particles_gt'][...]
   ```

2. **3D surface plots:** Use PyVista for high-quality plots:
   ```python
   grid = pv.StructuredGrid()
   # Create grid coordinates (X,Y) and set Z=height
   nx, ny = height_pred.shape
   x = np.linspace(xmin, xmax, nx)
   y = np.linspace(ymin, ymax, ny)
   X, Y = np.meshgrid(x, y, indexing='ij')
   Z = height_pred.T  # or appropriate transpose
   grid.points = np.column_stack([X.ravel(), Y.ravel(), Z.ravel()])
   grid.dimensions = [nx, ny, 1]
   plotter = pv.Plotter()
   plotter.add_mesh(grid, show_edges=False, opacity=0.7, color='lightblue')
   plotter.add_scalar_bar('Height')
   plotter.add_axes()
   plotter.show()
   ```
   - Repeat for `height_true`. Use consistent scale. Color maps and transparency enhance comparison.

3. **Lagrangian trajectories:** Scatter or line plots of particle paths:
   ```python
   pt_cloud = pv.PolyData(pts_pred)
   pt_cloud['velocity'] = np.linalg.norm(velocity_pred, axis=1)
   plotter2 = pv.Plotter()
   plotter2.add_mesh(pt_cloud, render_points_as_spheres=True, point_size=3)
   plotter2.add_axes()
   plotter2.show()
   ```
   - Color by speed or time for clarity.
   - Overlay true vs predicted paths to assess differences.

4. **Quantitative metrics:**
   - *PSNR* between predicted and true height fields:
     ```python
     mse = np.mean((height_pred - height_true)**2)
     max_signal = height_true.max() - height_true.min()
     psnr = 20 * np.log10(max_signal / np.sqrt(mse))
     ```
   - *Froude number similarity:* If $Fr=U/\sqrt{gL}$ should match, compare Froude values for predicted vs true bulk motion. Or compute similarity of velocity fields.
   - *Error norms:* Compute L2 or RMSE on particle positions over trajectories.

Example metrics in notebook:

```python
rmse_height = np.sqrt(mse)
print(f"Height RMSE: {rmse_height:.4f}, PSNR: {psnr:.2f} dB")
traj_err = np.mean(np.linalg.norm(pts_pred - pts_true, axis=1))
print(f"Avg particle position error: {traj_err:.4f}")
```

All plots and metrics can be compiled in the notebook. This visualization confirms whether SurfPINN accurately captures surface shapes and Lagrangian motion compared to SPH ground truth.

## 7. Docker & GKE+TPU Deployment

To ensure reproducibility and scalability, we containerize the entire environment.

**Dockerfile (example):**

```dockerfile
FROM nvidia/cuda:11.6.2-cudnn8-devel-ubuntu20.04

# Install Python and dependencies
RUN apt-get update && apt-get install -y python3-pip git
RUN pip3 install --upgrade pip

# Install JAX with GPU (and TPU if desired)
RUN pip3 install "jax[cuda11_cudnn82]" dm-haiku optax

# Install DualSPHysics (assuming pre-built binaries or clone & make)
# (We may need to compile DualSPHics from source)
RUN git clone https://github.com/DualSPHysics/DualSPHysics.git /opt/DualSPH
RUN cd /opt/DualSPH && ./make_localmachine.sh  # hypothetical build script

# Other libraries
RUN pip3 install h5py pyvista matplotlib

# Copy the SurfPINN code into container
WORKDIR /workspace
COPY . /workspace

# Set entrypoint or default command
CMD ["python3", "train_surfpinn.py"]
```

**docker-compose.yaml:**

```yaml
version: '3.8'
services:
  surfpinn:
    build: .
    runtime: nvidia
    environment:
      - NVIDIA_VISIBLE_DEVICES=all
    volumes:
      - ./data:/workspace/data
    ports:
      - "8888:8888"  # for Jupyter
```

**GKE & TPU setup notes:**

- **Container Registry:** Build the Docker image locally or via Cloud Build, then push to Google Container Registry (GCR) or Artifact Registry.
- **GKE Cluster:** Create a Kubernetes cluster with GPU nodes (or TPU nodes with TPU VM images). Use `gcloud container clusters create` with `--accelerator=type=nvidia-tesla-v100,count=1` (or TPU config).
- **Deploy SurfPINN:** Use a Kubernetes Deployment manifest referencing the pushed image. For example:
  ```yaml
  apiVersion: apps/v1
  kind: Deployment
  metadata: {name: surfpinn-deploy}
  spec:
    replicas: 1
    template:
      spec:
        containers:
        - name: surfpinn
          image: gcr.io/your-project/surfpinn:latest
          resources:
            limits:
              nvidia.com/gpu: 1  # for GPU
          command: ["python3", "train_surfpinn.py"]
        nodeSelector:
          cloud.google.com/gke-accelerator: nvidia-tesla-v100
  ```
- **TPU usage:** For TPUs, use [Cloud TPU VMs](https://cloud.google.com/tpu/docs/vm) or Kubernetes with TPU pods. Ensure the image has JAX built for TPU (bfloat16), and set environment variables like `XLA_FLAGS=--xla_force_host_platform_device_count=8` if using multiple TPU cores.
- **Storage:** Mount or attach persistent volume for HDF5 data and model checkpoints.
- **Monitoring:** Use TensorBoard or JAX profiler on the container to track training. Expose ports via `kubectl port-forward` if needed.
- **Cluster Config:** Use `gcloud` commands or Terraform to automate cluster creation, including autoscaling node pools with GPUs/TPUs.

By following these steps, the SurfPINN environment can be reliably built, shared, and scaled across cloud infrastructure.

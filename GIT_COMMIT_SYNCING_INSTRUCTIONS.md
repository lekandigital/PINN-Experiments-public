# Git Commit Syncing Instructions

## Overview

This project uses a dual-repository setup to safely manage sensitive credentials while maintaining a public-facing codebase:

- **Private Repo** (`PINN-Experiments-private`): Contains full project history with all credentials
- **Public Repo** (`PINN-Experiments-public`): Clean version with secrets filtered and research-docs excluded

## Quick Start

### Method 1: Using the sync script (recommended)

```bash
# 1. Make your changes and commit locally
git add .
git commit -m "Your descriptive commit message"

# 2. Sync to both repos
./sync-repos.sh "Your descriptive commit message"
```

This will:
1. Push to the private repo (with full content)
2. Sync to the public repo (with secrets replaced and research-docs removed)

### Method 2: Using the git alias

```bash
# 1. Make your changes and commit locally
git add .
git commit -m "Your descriptive commit message"

# 2. Use the alias to push and sync
git sync-push
```

This runs the same sync process but using a git alias.

## How the Syncing Works

### The sync-repos.sh Script

The script automates a multi-step process:

1. **Push to Private Repo**
   ```bash
   git push origin main
   ```
   - Pushes your local commits to `PINN-Experiments-private`
   - Contains full credentials and all content

2. **Clone/Update Public Repo**
   - Creates or updates a temporary public repo at `/tmp/PINN-Experiments-public`

3. **File Sync (with exclusions)**
   ```bash
   rsync --exclude='.git' --exclude='research-docs' --exclude='.secrets-filter.txt' ...
   ```
   - Syncs all files EXCEPT:
     - `.git/` - keep separate histories
     - `research-docs/` - keep private
     - `.secrets-filter.txt` - config file
     - `.claude/` - IDE cache

4. **Filter Secrets**
   - Reads `.secrets-filter.txt`
   - Replaces all occurrences of secrets in text files (.md, .sh, .yaml, .json, .py, .txt)
   - Example: `REDACTED_PASSWORD` → `REDACTED_PASSWORD`

5. **Commit and Push**
   - Commits the filtered version to public repo
   - Pushes to `PINN-Experiments-public`

### Why Two Separate Repos?

**Why not just use branches?**
- Branches share git history
- A determined person could check out old commits and find secrets
- Public repo must be fully clean with no credential traces

**Why not use git filters?**
- Filters only work on retrieval, not storage
- Secrets remain in the .git folder
- GitHub's search index would still find them

**Why not use environment variables?**
- Documentation needs examples (docs contain credentials)
- Easier for researchers to follow along with explicit values in test scripts
- Some files legitimately need those values during development

## Important Notes

### Local Working Directory

- You work in `/Users/lekan/Dev/PINN-Experiments` (points to private repo)
- This is your main working directory with full access to secrets
- All credentials and research-docs are safe here

### Public Temporary Directory

- The script maintains `/tmp/PINN-Experiments-public` as a working copy
- Automatically updated by `sync-repos.sh`
- Can be safely deleted anytime (script will recreate it)

### Git History Separation

- Private and public repos have **completely different commit histories**
- Each has its own independent git timeline
- Public commits are automatically generated by the sync script

### What NOT to Do

❌ Don't push directly to public repo
```bash
git remote set-url origin https://github.com/lekandigital/PINN-Experiments-public.git
git push origin main  # DON'T DO THIS
```

❌ Don't forget to run sync-repos.sh
```bash
git push origin main  # Only pushes to private!
# Must also run: ./sync-repos.sh "message"
```

✓ Do use the sync script
```bash
./sync-repos.sh "Your message"  # Handles both repos
```

## Troubleshooting

### Changes not appearing in public repo

**Problem**: You committed to private but public repo didn't update

**Solution**:
```bash
cd /Users/lekan/Dev/PINN-Experiments
./sync-repos.sh "Sync latest changes"
```

### Secret not being filtered

**Problem**: A credential is appearing in the public repo

**Solution**:
1. Add it to `.secrets-filter.txt`:
   ```
   your_secret==>REDACTED_VALUE
   ```
2. Run the sync again:
   ```bash
   ./sync-repos.sh "Filter new secret"
   ```

### Getting different behavior locally vs remote

**Problem**: Public repo looks different than expected

**Solution**:
- The script doesn't retain git history
- Each sync creates a fresh filtered copy
- This is by design (no secrets in any commits)
- Check `/tmp/PINN-Experiments-public` to see the exact state

## Script Configuration

### Edit `.secrets-filter.txt`

Format: `SECRET==>REPLACEMENT`

Example:
```
# Database credentials
db_password_xyz==>REDACTED_PASSWORD
admin_api_key==>REDACTED_API_KEY

# Network addresses
192.168.1.100==>REDACTED_IP
user@server.com==>REDACTED_EMAIL
```

### Edit `sync-repos.sh`

To exclude additional directories:
```bash
rsync -av --delete \
    --exclude='.git' \
    --exclude='research-docs' \
    --exclude='my_private_folder'  # Add here
    "$SCRIPT_DIR/" "$PUBLIC_DIR/"
```

## Git Alias

The `git sync-push` alias is configured globally and runs:
```bash
git push origin main && ./sync-repos.sh "$(git log -1 --format=%s)"
```

To view it:
```bash
git config alias.sync-push
```

To use it:
```bash
git commit -m "Your message"
git sync-push
```
